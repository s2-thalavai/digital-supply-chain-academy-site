Process mining for procure-to-pay and order-to-cash

Beginner lens. See what actually happens, not what the manual says.

Process mining reconstructs how processes really run from system event logs (case id, activity, timestamp, user). It discovers the actual flow and its variants, checks conformance against the intended process, and finds bottlenecks, rework and automation opportunities.

In plain words

Every click in the ERP leaves a timestamp. Put them in order per purchase order and you see what really happens: how often prices change after receipt, how often invoices arrive before the PO, and where things wait.

Architecture

An event log is a data product: consistent case ids and activity names across systems are the hard part.

  • Define the case notion (PO line, invoice, order)
  • Object-centric logs for many-to-many (PO ↔ invoices)
  • Mask user identities where privacy rules require

What can go wrong

Failure scenarioHow to handle it
Bad case idsFragments one process into many.
Mapping noiseSame activity named differently.
Insight without actionNo owner for improvements.
