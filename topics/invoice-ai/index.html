Invoice intelligence and AI automation

Beginner lens. Step through the pipeline and switch scenarios to see why some invoices need a person.

Invoice intelligence turns invoice documents (PDF, scans, photos, e-invoices) into validated, matched AP transactions with as little manual work as possible. It combines OCR, document AI extraction, business rules, matching and a human review queue for low-confidence or exceptional cases.

In plain words

A clerk used to type every invoice into the system. Now software reads the invoice, fills in the fields, checks them, and only asks a person when it is unsure or something looks wrong. The trick is knowing when to ask.

Architecture

Treat extraction output as untrusted data until validated. Hash the file for idempotency, keep the model output and the human-corrected version, and measure the touchless rate per supplier.

  • Async pipeline: upload → queue → workers → events
  • Confidence thresholds per field, not one global number
  • Never let text inside an invoice act as an instruction to an LLM
  • Keep a golden test set per supplier layout to catch model drift

What can go wrong

Failure scenarioHow to handle it
Total misread (1,098,580 vs 109,858)Arithmetic validation catches it: lines + tax must equal total.
Same invoice re-scannedFile hash differs; business-key duplicate check (supplier + number) still catches it.
Bank account on invoice differs from masterFraud signal: block, never auto-update master data from a document.
