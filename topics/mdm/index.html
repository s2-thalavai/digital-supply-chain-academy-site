Master data management

Beginner lens. Clean shared data, entered once.

Master data is the shared, slow-changing data every transaction depends on: products, suppliers, customers, locations, prices and the chart of accounts. Master data management (MDM) creates one trusted "golden record" per entity, with ownership, workflow, quality rules and distribution to every system.

In plain words

If "Acme Displays", "ACME DISPLAYS PVT LTD" and "Acme Disp." are three suppliers in the system, spend reports are wrong and you might pay the same invoice twice. MDM makes them one.

Architecture

Each master entity has one owner system and one steward team. Publish changes as versioned events; consumers never edit master data locally.

  • Cross-reference table maps golden id ↔ each system id
  • Survivorship rules decide which source wins per attribute
  • Sensitive fields (bank) need maker-checker

What can go wrong

Failure scenarioHow to handle it
Duplicate suppliersSplit spend, duplicate payments.
Product data mismatchWrong unit of measure → quantity exceptions.
Local editsSystems drift apart; enforce publish-subscribe.
