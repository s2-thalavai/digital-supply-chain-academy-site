Store fulfilment app (BOPIS and ship-from-store)

Store associates pick, handle shorts, and hand over orders; capacity-aware routing.

Problem

Stores fulfilling online orders need a fast picking flow, a clear process when the shelf is empty, and protection from overload during peak.

Architecture

Request flow

OMS (omni-retail)
store-fulfilment-service
PWA
notification-service
OMS short/complete events

Learning outcomes

  • Mobile-first PWA design
  • Short-pick handling and inventory feedback
  • Capacity-aware sourcing
  • Customer notifications

MVP

  • Pick list per store with priority by promise time
  • Scan to confirm; mark short → reallocate request to OMS
  • Ready-for-pickup notification with pickup code
  • Hand-over with code verification
  • Store capacity (orders/hour) respected by routing

Stretch

  • Offline mode with background sync
  • Substitution suggestions
  • Curbside arrival check-in

Services

ServiceResponsibility
store-fulfilment-serviceTasks, picks, shorts, capacity
notification-serviceEmail/SMS/push via provider port
store-pwaReact PWA for associates

Entities

EntityFields
StoreTaskorderNo, store, lines[], dueBy, status
PickLinesku, qty, picked, short
StoreCapacitystore, slot, max, used

APIs

EndpointPurpose
GET /stores/{code}/tasksPick queue
POST /tasks/{id}/lines/{sku}/pickScan confirm
POST /tasks/{id}/shortReport short
POST /tasks/{id}/handoverVerify pickup code

Events

Topic / eventMeaning
store.pick.shortOMS re-sources; cycle count requested
store.order.readyNotify customer
store.order.collectedComplete order

Stack

Backend
Java 21 · Spring Boot 3
Database
PostgreSQL 16 · Flyway
Events
Apache Kafka (KRaft) · Apicurio · CloudEvents
UI
React PWA · Workbox (offline) · ZXing barcode scanning
Identity
Keycloak (OIDC)
Observability
OpenTelemetry · Prometheus · Grafana · Tempo
Runtime
Docker Compose locally · Helm on any Kubernetes
Testing
JUnit 5 · Testcontainers · Pact
Notifications
NotificationPort with SMTP (Mailpit locally) and webhook adapters

Non-functional requirements

  • Scan-to-confirm under 200 ms on 4G
  • Works offline for 30 minutes

Testing

  • Playwright mobile viewport flows
  • Kafka contract tests with OMS

Plan

  • W1: tasks and picking API
  • W2: PWA and scanning
  • W3: shorts, notifications, capacity
  • W4: offline, demo

Portfolio deliverables

  • Phone-recorded demo
  • UX notes for store associates
