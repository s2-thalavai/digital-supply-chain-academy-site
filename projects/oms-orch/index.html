Order orchestration and holds

Order state machine, partial cancels, fraud/payment holds, ship-to-store fallback.

Problem

omni-retail reserves and routes; real orders also pause for fraud checks, wait for payment, get partially cancelled and need a fallback when a pickup store is short.

Architecture

Request flow

Order API
Temporal workflow
reservation (omni-retail)
fraud port
WMS / store
status events

Learning outcomes

  • Durable workflow orchestration
  • State machine design
  • Compensation (saga) patterns
  • Policy-driven holds

MVP

  • Order workflow: CREATED → HELD? → RELEASED → SHIPPED → DELIVERED
  • Fraud and payment holds with release/cancel
  • Line-level partial cancellation releasing reservations
  • BOPIS short → ship-to-store transfer from nearest DC

Stretch

  • SLA timers: auto-cancel unpaid orders
  • Customer service console for overrides
