AP automation platform

Capture → extraction → validation → matching → review → posting, end to end.

Problem

Invoice-rag answers questions about invoices; real AP needs those invoices validated, matched to POs and receipts, reviewed by people when unsure, and posted to the ledger.

Architecture

Request flow

Mailbox / upload
object storage
extraction workers
validation
matching
review UI
ledger

Learning outcomes

  • Async document pipeline
  • Human-in-the-loop design
  • Confidence calibration with rule evidence
  • Integration with P2P core and matching engine
  • Touchless-rate measurement

MVP

  • Ingest by upload and mailbox (IMAP adapter)
  • OCR + field/line extraction behind an ExtractionPort
  • Validation: arithmetic, mandatory fields, GSTIN, duplicates
  • Matching via the matching engine
  • React review queue: side-by-side image and fields, keyboard-first
  • Post approved invoices to ledger-service

Stretch

  • Per-supplier layout learning from corrections
  • Early-payment discount optimiser
  • Supplier status portal

Services

ServiceResponsibility
capture-serviceHashing, storage, queueing
extraction-serviceOCR and field extraction (Python)
validation-serviceRules and duplicate checks
review-serviceQueue, assignments, SLAs
posting-serviceRate-limited posting

Entities

EntityFields
Documentid (sha256), source, status, pages
ExtractedInvoicedocumentId, fields{value, confidence, bbox}, lines[]
ReviewTaskinvoiceId, reasons[], assignee, dueAt, decision
Correctionfield, before, after, user

APIs

EndpointPurpose

Non-functional requirements

  • Idempotent on file hash and on supplier + invoice number
  • Document text never treated as instructions
  • PII masked in logs

Testing

  • Golden set of 100 invoices with expected fields
  • Pipeline chaos test: kill workers mid-batch, no duplicates

Plan

  • W1: capture and storage
  • W2: extraction adapters
  • W3: validation and duplicates
  • W4: matching integration
  • W5: review UI
  • W6: posting, metrics, demo

Portfolio deliverables

  • Demo: clean, low-confidence, duplicate, fraud scenarios
  • Metrics dashboard screenshot
